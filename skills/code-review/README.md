# Code Review

![Иллюстрация процесса ревью кода](assets/code-review.svg)

**Code Review** — навык для системного анализа изменений в коде без редактирования файлов. Он помогает находить ошибки, риски безопасности, проблемы с обработкой сбоев и пробелы в тестах до того, как изменения попадут в основную ветку. Результат строится только на проверяемых фактах: конкретном diff, требованиях задачи, окружающем коде и доступных результатах тестов.

## Зачем нужен этот навык

Даже небольшой pull request может затрагивать больше сценариев, чем видно из изменённых строк. Новая проверка способна нарушить обратную совместимость, обработчик ошибки — скрыть причину сбоя, а корректный на первый взгляд путь — допустить утечку данных. Навык задаёт единый порядок ревью и помогает сосредоточиться на **последствиях изменения**, а не на вкусовых предпочтениях автора.

## Что проверяется

- соответствие реализации заявленным требованиям;
- корректность основной логики и граничных сценариев;
- валидация входных данных, путей, прав доступа и секретов;
- сохранность данных при ошибках, повторах и конкурентном выполнении;
- качество диагностики и отсутствие чувствительных данных в логах;
- тесты для успешных, ошибочных и регрессионных сценариев;
- поддерживаемость кода и понятность пользовательского поведения.

## Как проходит ревью

1. Определяется точный объём изменений: diff, задача и инструкции репозитория.
2. Изучаются изменённые файлы, связанные компоненты и существующие тесты.
3. При возможности запускаются сфокусированные проверки, подтверждающие выводы.
4. Каждая проблема оценивается по влиянию и подкрепляется ссылкой на файл и строку.
5. В конце формулируются сильные стороны, пробелы тестирования и итоговый вердикт.

> [!IMPORTANT]
> Навык работает в режиме **только чтение**. Он не исправляет найденные проблемы и не изменяет файлы проекта.

## Уровни замечаний

| Уровень | Когда используется |
| --- | --- |
| **Critical** | Изменение может привести к уязвимости, потере данных, серьёзному сбою или блокировке выпуска. |
| **Important** | Есть функциональная ошибка, существенный неподдержанный сценарий или высокий риск регрессии. |
| **Minor** | Улучшение снижает технический долг или делает код понятнее, но не блокирует выпуск. |

Каждое замечание содержит **местоположение**, доказательство проблемы, описание влияния и конкретную рекомендацию. Если значимых проблем нет, отчёт прямо сообщает об этом и перечисляет выполненные проверки.

## Пример запроса

```text
Проведи ревью изменений в текущей ветке относительно main.
Особенно проверь авторизацию, обработку повторных запросов и тесты.
Файлы не изменяй.
```

Пример ожидаемого фрагмента ответа:

```text
Important — src/orders/service.ts:84
Повторная отправка запроса создаёт второй заказ, потому что ключ
идемпотентности не проверяется. Это может привести к двойному списанию.
Рекомендация: сохранять и повторно использовать результат по ключу запроса.
```

## Формат результата

Отчёт начинается с находок, сгруппированных по критичности. После них идут **сильные стороны**, непроверенные области, недостающие тесты и финальный вывод: можно ли принимать изменение или требуется доработка. Такой формат позволяет быстро увидеть блокирующие риски и одновременно сохранить контекст для автора.

## Ограничения

Качество ревью зависит от доступного контекста. Если требования, diff или окружение не предоставлены, выводы будут уже. Отсутствие замечаний не доказывает полную корректность системы: ревью дополняет автоматические тесты, статический анализ и ручную проверку, но не заменяет их.

Для повторяемой проверки используется шаблон [`templates/review-checklist.md`](templates/review-checklist.md). Основные правила поведения навыка находятся в [`SKILL.md`](SKILL.md).
